# 精准回归 Skill

## 用途

用于根据代码变更、PR 信息、接口变化、历史缺陷和自动化结果，生成精准回归测试范围、风险级别和执行建议。

实现或扩展本 Skill 前，必须先阅读：

1. `docs/architecture/agentic-qa-blueprint.md`
2. `references/research/agentic-qa-research-guide.md`

非必要情况不得自研回归平台，应优先复用 Git、CI、Pytest、Allure、测试用例库和成熟质量分析工具。

## 输入要求

尽量收集：

- Git diff 或变更文件列表
- PR / 需求 / 缺陷背景
- 影响接口、页面、任务或数据表
- 历史缺陷和历史失败记录
- 自动化用例清单和最近执行结果
- 上线范围和风险模块

缺少信息时必须标注“待确认”，不要自行推断成事实。

## 分析步骤

1. 识别变更类型：前端、后端、接口、数据、配置、依赖、测试代码。
2. 识别直接影响范围：模块、接口、页面、任务、数据表。
3. 识别间接影响范围：上下游依赖、权限、状态流转、缓存、消息、定时任务。
4. 关联历史缺陷和高频失败区域。
5. 按 P0/P1/P2/P3 给出回归优先级。
6. 区分自动化可覆盖项和人工探索项。
7. 输出最小但可信的回归清单。

## 输出要求

建议使用 `templates/regression_selection_template.md`。

必须包含：

- 变更摘要
- 影响范围
- 风险级别
- 推荐回归清单
- 自动化执行建议
- 人工补充测试建议
- 待确认信息
- 不执行或暂缓项说明

## 禁止事项

- 不只按文件路径机械判断影响范围。
- 不编造接口、页面、字段、状态或历史缺陷。
- 不建议无审批执行高风险操作。
- 不自研回归选择平台。
- 不把当前公司业务规则写成通用规则。
