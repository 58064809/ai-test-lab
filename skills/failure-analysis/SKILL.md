# 自动化失败分析 Skill

## 用途

用于基于日志、堆栈、Allure 报告、请求响应、截图和环境信息分析自动化失败原因，并输出证据链、重跑建议和缺陷判断。

实现或扩展本 Skill 前，必须先阅读：

1. `docs/architecture/agentic-qa-blueprint.md`
2. `references/research/agentic-qa-research-guide.md`

非必要情况不得自研报告平台或失败分析平台，应优先复用 Pytest、Allure、ReportPortal、CI 日志和现有日志系统。

## 输入要求

尽量收集：

- 失败用例名称
- 失败时间和环境
- 报错堆栈
- 请求参数与响应
- Allure / pytest / CI 报告摘要
- 应用日志、traceId、requestId
- 截图、录屏、浏览器 console 或 network 信息
- 最近代码变更或配置变更

缺少信息时必须标注“待确认”。

## 失败分类

| 类型 | 判断线索 |
| --- | --- |
| 脚本问题 | 选择器失效、断言错误、等待不足、测试数据准备错误 |
| 数据问题 | 前置数据不存在、状态不符合、脏数据、重复数据 |
| 环境问题 | 服务不可用、网络超时、依赖异常、配置不一致 |
| 业务 Bug | 返回值错误、状态流转错误、金额/库存/权限计算错误 |
| 第三方问题 | 支付、短信、OCR、风控、外部 API 异常 |
| 非稳定失败 | flaky、偶发超时、并发冲突、资源竞争 |

## 输出要求

建议使用 `templates/failure_analysis_template.md`。

必须区分：

- 已确认事实
- 合理推断
- 待确认项

必须包含：

- 失败摘要
- 关键证据
- 初步归因
- 影响范围
- 是否建议重跑
- 是否建议提 Bug
- 后续排查步骤

## 禁止事项

- 不把推测原因写成确认根因。
- 不编造日志、SQL、接口响应或截图。
- 不省略证据链。
- 不把所有失败都归因于业务 Bug。
- 不自研复杂失败分析平台。
