# AI 输出评估标准

## 用途

用于评估 Agent 在测试任务中的输出是否可信、完整、可执行，并决定是否可以沉淀为 Prompt、Skill、Workflow 或 Template。

## 评估维度

| 维度 | 说明 |
| --- | --- |
| 完整性 | 是否覆盖核心业务路径、异常路径、边界条件和风险点 |
| 正确性 | 用例、断言、数据和结论是否符合输入材料，不编造业务规则 |
| 可执行性 | 输出是否能直接用于评审、测试设计、执行、排查或报告 |
| 可维护性 | 结构、命名、分层和表达是否便于长期复用 |
| 可追溯性 | 结论是否能追溯到需求、代码变更、日志、报告或缺陷证据 |
| 稳定性 | 是否避免依赖脆弱假设、偶发环境状态或不可控输入 |
| 安全性 | 是否避免泄露敏感信息，是否遵守最小权限和只读边界 |
| 可解释性 | 是否区分事实、推断和待确认项，说明判断依据 |

## 常见扣分项

- 漏掉关键测试场景。
- 生成输入中不存在的接口字段、页面元素、状态或业务规则。
- 把推测根因写成确认结论。
- 输出泛泛建议，缺少可执行步骤。
- 忽略权限、数据一致性、幂等性、并发或异常路径。
- 给出无法运行或缺少依赖说明的脚本。
- 绕开当前项目边界，建议自研复杂平台或开放高风险工具。

## 评分建议

每个维度可按 0～5 分评估：

| 分数 | 含义 |
| --- | --- |
| 0 | 完全不可用，偏题或违反边界 |
| 1 | 基本不可用，仅少量相关内容 |
| 2 | 可参考但缺失明显，需要大量人工改写 |
| 3 | 基本可用，需要少量调整 |
| 4 | 质量较好，可直接使用或轻微修改后使用 |
| 5 | 专业、完整、结构清晰，可直接沉淀 |

## 使用方式

1. 先确认任务输入是否足够。
2. 再按维度检查 AI 输出。
3. 对事实、推断、待确认项分别标注。
4. 判断后续动作：保留原样、沉淀 Prompt、沉淀 Skill、沉淀 Workflow、沉淀 Template、需要接入成熟工具或暂缓处理。
